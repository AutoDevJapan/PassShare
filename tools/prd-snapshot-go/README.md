# Private production snapshot

This verification/deployment helper captures only the reconciled PassShare production PG18 service. It uses the existing Railway CLI authentication, never retrieves DB connection values, and does not provision a public TCP proxy, service, volume, or paid backup.

The wrapper validates the production resource IDs and clean main source. The helper checks the actual project/workspace, generates a temporary SSH identity for the same existing principal, and revokes only the ID returned by this call. Cleanup failure is a deployment failure. An existing registered identity can be used for manual OAuth capture without copying, registering, or removing it.

Before registration, an exclusive non-secret `.ssh-key-recovery.json` record is written next to the output. It contains the actual workspace, unique registration name, public-key SHA-256, and the returned key ID when available. A lost registration reply or empty ID stops capture and preserves this descriptor on disk and in the failure log. Reconcile that exact name and public-key digest with the workspace's key metadata to obtain the exact ID before revocation; never infer an ID or remove other keys. Successful revocation removes the descriptor. SIGINT and SIGTERM cancel capture and run revocation with a separate cleanup deadline. SIGKILL, runner loss, and remote-shell loss can interrupt cleanup; these are not claimed as verified absence. For an interrupted remote capture, inspect and remove only the exact temporary path established for that invocation, never a wildcard of other jobs' files.

The database container creates a private temporary archive, checks it with its own `pg_restore`, emits the source SHA-256 and base64 bytes, then verifies temporary-file absence. The helper verifies the complete decoded bytes against that digest and creates its output without overwrite, outside the upload tree. No database content, connection value, or private identity is printed. The caller must remove the job-local archive; it must not upload it as a GitHub artifact or count it as a retained backup.

Before requesting an archive, the helper runs a fixed `printf` readiness command with the same registered identity, project, environment and database service. This does not read database rows or create a dump. Only a classified SSH connection timeout permits another readiness attempt: at most three attempts, each bounded by 25 seconds, with a cancellable two-second wait. Identity rejection, host-key mismatch, provider rejection, an unexpected reply and an unclassified error stop immediately. Archive capture and transfer are attempted once; an error after readiness is not retried. The existing four-minute request deadline includes registration, readiness and capture, with a separate 45-second revocation deadline.

The Railway CLI spawns a separate SSH process. Windows therefore creates the CLI suspended, assigns it to an owned kill-on-close Job Object, then resumes its verified primary thread; Linux creates a dedicated process group. On cancellation, deadline or a parent exit with inherited pipes still open, the helper terminates only that owned scope, waits for descendants to stop and output readers to finish, then proceeds to identity revocation. Windows retains verified member handles and requires their exit signals, not only zero active processes. It compares the job's lifetime process count before enumeration and after termination; a descendant spawned during that interval makes recovery unconfirmed rather than pretending an incomplete handle inventory was sufficient. Process termination and pipe recovery have bounded five-second waits in addition to the command budget. It never treats `WaitDelay` or the direct parent's exit alone as proof that the descendants have stopped. If local process recovery is unconfirmed, it fails without retry and preserves the temporary identity and exact non-secret recovery descriptor for scoped recovery. It does not infer that closing the local SSH process proves a remote dump stopped or its trap completed; remote cleanup after an interrupted capture still requires readback.

Diagnostics distinguish scope verification, identity registration, readiness and revocation. Fixed remote stderr markers identify whether a failed capture reached the archive command or completed its database-side validation; no marker means that stage is unobserved, not proof that no remote work began. Raw stderr remains private. Two earlier first attempts timed out before archive validation, while their single failed-job retries succeeded. For the later incident, both services had active deployments and sleep disabled before the local read-only probe. These observations do not establish a serverless, credential-propagation, DNS or routing root cause; the bounded readiness path improves failure isolation without claiming that root cause has been identified.

Run isolated tests with `go test ./...` and `go vet ./...` from this directory. These do not contact Railway. The production wrapper invokes the helper with `--output` inside its owned private temporary directory. A manual existing identity is supplied only through `--identity-file`.

Its fingerprint is `SHA256:+S1xg92FrnHz6pY3bpkmh1OGtWQGNANXilPzlxA7B1g`. The exact `ssh.railway.com` host block keeps strict host checking, batch mode and the explicit identity only, and bounds connection/handshake waiting with `ConnectTimeout 15` and `ConnectionAttempts 1`. Railway uses the system SSH client as described in its [official CLI documentation](https://docs.railway.com/cli/ssh). It does not trust an unauthenticated key scan, disable verification, or copy the owner's private key. A rotated or mismatched host key fails until its provenance is reconciled. Failure logs expose fixed diagnostic classes, stages and exit codes, never raw SSH/database stderr. Earlier manual OAuth capture and later successful CI captures are separate evidence; neither proves that every future cloud connection will succeed.
