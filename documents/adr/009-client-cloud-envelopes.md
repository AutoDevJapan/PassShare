# ADR 009: 端末側で作るクラウド暗号化データ

状態: 暗号化の基礎を実装。製品への接続・共有・復旧の受入は未完了。
共有ToDo #1163 / #1175、M4。

## 決定

項目全体のJSONを端末でXChaCha20-Poly1305により暗号化する。
既存のRust Coreと同じ方式・OSの乱数・鍵の破棄を再利用する。
パスワードボックスごとに独立した256bitの鍵を生成し、書き込みごとに新しい192bitのnonceを生成する。
サーバーへ送る型は暗号文、nonce、識別子・版・鍵の世代だけを持つ。
秘密の鍵はSerialize・Debugを実装せず、破棄時に消去する。

認証付き暗号化の追加データには、方式の名前・形式の版・ボックスID・項目ID・項目の版・鍵の世代を含める。
復号では取得先から別に決めた期待値を渡す。受信した追加データを、そのまま期待値として採用しない。
識別子の付け替え、古い版、異なる世代へ暗号文だけを移す操作を拒否する。
復号したJSONのID・ボックスID・版も照合する。
項目の追加フィールドと複数URLは投影せず全体で保持する。

所有者の鍵包みは、端末内のアカウント用ルート鍵で暗号化する。
追加データは所有者アカウントID、ボックスID、鍵の世代、項目暗号化とは別の用途に固定する。
認証パスワード変更APIへ復号鍵を送らない。
ここで用意した鍵包みは所有者用であり、他の利用者への鍵配布ではない。

## 入力の契約

識別子は既存の26文字の形式を検査する。版と世代は正の、JSONで整数を保てる範囲に限る。
項目は1MiB以内・容器の深さ127以内に制限し、復号のJSONパーサーの上限と揃える。
計数して必要な容量を先に確保し、平文の再確保・上限を超える全体の追加確保を防ぐ。
nonce・暗号文は復号前に長さと形式を検査する。
平文の一時バイト列と秘密鍵を破棄する。暗号依存のzeroize機能を有効にし、内部の鍵コピーも破棄する。
復号後のJSONは呼び出した端末が管理する。
鍵・平文・秘密値をエラーやテストの表示へ含めない。

## 次の接続と受入

WebのWASM、Desktop/Mobile、拡張、Rust SDK/CLI/各SDKへ同じ契約を接続する。
秘密の鍵をバックエンドへ渡す方式に置き換えない。
共有には確認した受信者の鍵・指紋、失効には新しい鍵の世代と以後のデータの再暗号化が必要。
既に受け取った秘密値を相手の記憶から消せるとは説明しない。
復旧は端末側の鍵包みと現在の本人・権限の照合を含め、古いバックアップを承認に使わない。
既存平文データは所有者の操作で移行し、全JSON・添付・版・再読取・失敗時の元データ保持を確認する。

Rustの基礎試験だけで、DB暗号化や端末間共有が完成したとはしない。
UIの方向は画像で確認し、料金・公開の既存条件も維持する。
