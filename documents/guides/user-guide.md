# PassShare ユーザーガイド

> Issue [#111](https://github.com/AutoDevJapan/PassShare/issues/111)  
> Web: `/docs/user-guide`  
> 最終更新: 2026-10-11

## 概要

初回セットアップから日常利用まで、PassShare のパスワードボックス操作を説明します。

## 1. アカウント作成

Web ポータル（`/app/signup`）でクラウド用のアカウントを作成します。端末版の .pbox はアカウントなしで使えます。マスターパスワードは端末ファイルを開くためのもので、クラウド用のアカウントパスワードとは別です。

クラウドには、Webの所有者暗号化モードとConnect互換モードがあります。所有者暗号化モードは、ログイン用とは別の暗号化パスワードと端末内のRust/WASM Workerで項目を暗号化し、サーバーは項目の内容を読めません。Connect互換モードはサーバーが内容を読めます。所有者暗号化モードは実装済みですが、利用先の暗号化APIが有効な場合に限ります。新規設定は空のパスワードボックスが対象です。既存の互換項目の移行と全クライアントの暗号化対応は未完です。

一般向けの配布と販売は検証中です。利用中の版と配布元の機能説明で対応を確認してください。CI成果物やソース実装だけでは、署名・対応OSでの導入・一般向け配布を確認できません。開発者向けの起動手順は [デスクトップ開発手順](../runbooks/local-dev-desktop.md) を参照してください。

## 2. パスワードボックスを開く

- **Desktop:** `.pbox` ファイルを選択し、マスターパスワードで開く
- **Web:** ログイン後、ボックスの保管方式を確認。所有者暗号化モードでは別の暗号化パスワードで解除

## 3. ログイン情報の管理

| クライアント | 操作 |
|-------------|------|
| Web | `/app/vaults` → パスワードボックス選択 → CRUD |
| Desktop | 項目追加・検索・コピー（クリップボード自動消去） |
| Mobile / Extension | Connect互換モード。所有者暗号化モードへの接続は未対応 |

DesktopのConnect接続も互換モードです。CLIの明示的な暗号化モードは通常のConnect接続と別の所有者向け経路であり、全クライアントの対応や端末ファイルの復旧操作を示すものではありません。

## 4. クラウド同期（Desktop）

設定 → クラウド同期でConnect互換モードへpush / pull。端末ファイルの暗号化は、同期先の内容をサーバーから隠すものではありません。競合時はローカル優先またはクラウド優先を選択。

## 5. データ移行

1Password から 1PUX インポートまたは CSV エクスポート → PassShare インポート。

## 6. バックアップと復旧

端末の復旧対応版では、復旧が有効な `.pbox` ファイルと緊急キットのコードで開き、新しいマスターパスワードを設定できます。旧ファイルは、現在のマスターパスワードで事前に復旧を有効化してください。通常の保存だけでは旧ファイルの復旧は有効になりません。復旧が無効なファイルは、コードだけで開けません。

ファイルの控えとコードは別々に安全に保管してください。コードだけでは紛失したファイルを取り戻せません。端末ファイルの復旧はRust Coreに実装済みですが、デスクトップの復旧画面は統合し、Linuxの実画面で検証済みです。利用中の版がファイル形式と復旧操作に対応するか、配布元の機能説明で確認してください。旧版が対応するとは限りません。詳細は [端末ファイルの復旧仕様](../spec/local-key-recovery.md) を参照してください。

Webの所有者暗号化モードは別の復旧です。所有者としてログインし、現在の鍵世代に対応する控えファイルとコード、新しい暗号化パスワード、現在のログイン用パスワードを使います。ログイン用パスワードの再設定だけでは暗号化データは復旧できません。鍵世代の変更後は控えを作り直してください。詳細は [暗号化したパスワードボックスの復旧](../spec/encrypted-key-recovery.md) を参照してください。

CSV は平文で、追加フィールド・添付・複数 URL 等のすべてを保全するバックアップではありません。取込後に件数と内容を確認し、元データを検証前に消さないでください。
