# 1PUX の保存前検査（2026-10-05）

1PUX の後半に不正なカテゴリがあると、エラーを返しても前半の項目が保存されていた。ファイルを修正して再取込すると前半が重複するため、全項目の変換・入力検査を保存開始前へ移した。既存 API の入力検査順序だけを修正する。関連: [Issue #598](https://github.com/AutoDevJapan/PassShare/issues/598)、製品監査 S1・M2、共有 ToDo 1163・1599。

## 実装と範囲

- `backend/src/connect/router.js`: 抽出した全項目を既存の変換・検査に通す。全件成功後に既存の逐次保存を行う。
- 入力検査の失敗時は保存を開始しない。HTTP の応答形式、成功時の項目順、権限確認、保存処理は維持する。
- 保存工程の DB 障害、通信切断、成功応答の喪失に対する一括処理や再送時の重複防止は未実装。この変更を完全な移行やバックアップの証拠としない。

## 検証

基準は main `eba72ca`。実ユーザーの情報を使わず、架空データとメモリ内の保存先を使用した。

| 検証 | 修正前 | 修正後 |
|---|---|---|
| 3項目の先頭・中間・末尾を不正にし、実 HTTP で取込 | 先頭は保存0件。中間・末尾は正常な先行項目が保存され、既存一覧との全文一致検査が失敗 | 全位置で400を返し、保存0件。既存項目の全文・件数が不変 |
| 不正カテゴリを直し、同じ項目を再取込 | 中間・末尾の検査が失敗し、再取込の検証へ到達せず | 201・追加3件。各題名・カテゴリ・フィールドが一致し、既存データは不変 |
| API の既存拡張テストと上記3ケース | 成功11件・失敗2件 | 成功13件・失敗0件・省略0件 |
| Backend のテスト全体 | 今回の修正前には全体を実行していない | 成功100件・失敗0件。DB・CLI が必要な7スイートは対象環境がなく省略 |

オーナーの Chrome の新規タブで、実際の Web と API を起動して架空アカウントを作成した。2項目のうち後半が不正な入力を取込むとエラーになり、再読込後も項目は0件だった。カテゴリを修正した入力を取込むと成功の案内と2件だけが表示された。これは既存の簡易 JSON 入力を使用した確認であり、実際の 1Password ZIP、PostgreSQL、端末アプリ、完全な形式対応の検証ではない。

自分の Chrome タブと Web/API の検証プロセスは終了した。画面画像は製品専用の Discord スレッドへ直接添付する。Rust のビルド、GPU、API キー、顧客データは使っていない。
