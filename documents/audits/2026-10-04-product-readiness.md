# PassShare 製品監査（2026-10-04）

PassShare は、端末内で暗号化するデスクトップ版と、サーバーが項目を扱うクラウド版を実装している。現時点では、法人向けの有料サービスとして販売開始できるという証拠が不足している。説明を正し、データ消失・招待のなりすまし・復旧不能を解消してから、料金と公開を承認する。

### 説明と実装が食い違う箇所

1. PostgreSQL は項目の JSON を保存して返す。Web はパスワードを API に送る。クラウドを「サーバーが秘密値を読めない」「端末間暗号化済み」と説明できない。端末内の `.pbox` の暗号化とは別である。
2. 緊急キットの値は暗号化した本文に保存される。`PasswordBox::open` はマスターパスワードだけで開く。キットの値だけで開く処理はないため、紛失時に復旧できるという表示は誤り。
3. ランディングのダウンロードは同じページの見出しへ戻る。共有や移行を「予定」と表示している一方、実装は存在する。他社の使いやすさを劣るとする比較には根拠がない。
4. `production-v2.md` の Epic 完了は実装作業の記録であり、署名された配布物、ストア公開、法務承認、障害からの復旧を確認した販売判定ではない。

## 誰が対価を払うか

最初の候補は、専任の IT 担当がいない小規模企業と、顧客へ IT 導入を支援する会社。価値は「保管する機能」だけでなく、日本語での移行支援、担当者交代、復旧演習、問い合わせ対応まで一緒に提供することにある。これは顧客への聞き取り前の仮説であり、販売実績ではない。

個人向けの安価な保管機能だけで競合を上回る根拠はない。大企業向け SSO・端末管理・監査認証の営業は、現状の実装と運用に合わない。

## 競合と価格の現実

2026-10-04 に各社の公式料金ページを確認した。USD 表示を円へ換算して比較せず、年間契約・最低人数・機能の条件を合わせる。価格は変わるため見積もり前に再確認する。

| 製品 | 公式ページで確認できた料金条件 | PassShare への示唆 |

## 優先順位

Must は販売する構成で必須。端末単独の支援契約でも M1/M2/M6/M7/M8 を満たす。クラウド契約には全 Must が必要。これらを外して「完成」としない。

| ID | 優先度 | 直すこと・理由 | 合格条件・現状 |
|---|---|---|---|
| M1 | Must | 暗号化・復旧・配布・互換性の説明を実装に合わせる。顧客が誤った前提で秘密値を預けるのを防ぐ | ja/en/ru の Web、アプリ、文書を一致させ、実在する導線を実ブラウザで確認。着手 |
| M2 | Must | 項目編集で追加フィールドを消さず、保存失敗と競合を知らせる。CSV を完全なバックアップと誤認させない | 拡張フィールド・複数 URL を残す。二人の編集で上書きが起きず、失敗時に入力が残る。着手 |
| M3 | Must（クラウド） | 招待先の本人確認。任意のアドレスで登録して招待を受けられると会社の秘密値が漏れる | アドレスの所有確認か、管理者が本人を確認して承認する手順をサーバーで強制。取消・期限・競合を含む否定テスト |
| M4 | Must（クラウド） | クラウドでの項目暗号化と鍵の扱いを実装する | DB とサーバーに復号鍵を置かず、共有・失効・復旧・既存データ移行を全クライアントで検証。平文互換 API は顧客が管理する環境に限定し、制約を説明 |
| M5 | Must（クラウド） | アカウント復旧・パスワード変更・追加の本人確認・退会を整える | パスワード変更で旧セッション失効。復旧を悪用できず、退会後の保管期間と共有データの扱いを説明。画面だけの「リセット」は未実装 |
| M6 | Must | 端末の放置時・背景移行時にボックスを閉じ、実際に復旧できる仕組みと保存を確認 | モバイル #408 と WebView #409 を解消。緊急キットを使った復旧か、復旧不可の正確な案内。保存失敗・再起動・旧形式の受入テスト |
| M7 | Must | 一般利用者が入手・更新できる配布物と対応環境を確定する | 署名・更新・導入・アンインストールを対象 OS で確認。モバイル・拡張は #153/#154 公開前に利用可能として売らない |

## 検証と販売判定

1. 架空の利用者で登録→ボックス作成→項目追加→編集→出力→共有→削除→ログアウト→再ログインを試す。
2. 通信失敗、権限喪失、二人の同時編集、取込の途中失敗、アプリ再起動を試す。実データを表示しない。
3. Web を 320px とデスクトップ幅で確認し、画像を依頼スレッドへ直接添付する。
4. Issue→PR→適切なテスト→別モデルのセルフレビューで Must を解消→全 CI 成功→マージ。実装と検証の結果はこの報告へ追記する。
5. [料金・提供範囲案](../spec/commercial-packaging.md) の承認と M1–M8 の証拠が揃うまで販売可とは判定しない。公開・料金・支出はオーナーが決める。
