# 復旧キー・アカウント復旧・退会の画面

共有ToDo #1163 / #1174、販売条件M4 / M5の画面。APIは `account-recovery.md` と `account-retirement.md` を使う。
公開、課金、端末内の暗号化ファイルや将来の暗号鍵の復旧の承認ではない。

## 承認された画面

2026-10-08T03:07:56.076Z（日本時間12:07:56）のオーナー投稿1557590341639475231「a」は、
`recovery-retirement-proposal.png` の3画面案だけを承認する回答として反映する。他の画面案や
新しい文言には適用しない。承認された内容は次の3画面で、色・余白・部品は既存のアカウント画面と同じ。

1. 復旧キーを保管する（ログイン中、現在のパスワードで再認証して発行し、一度だけ表示する）
2. アカウントを復旧する（未ログイン。メールアドレス、復旧キー、新しいパスワード、確認）
3. 共有を引き継いで退会する（現在のパスワード、引き継ぐ相手、確認用メールアドレス）

発行後の画面では、再発行を誤って押さないよう発行フォームを外し、キー・注意書き・戻るリンクだけを表示する。
所有者が必要な共有ボックスが複数あるときは、同じ「引き継ぐ相手」と「所有者を移譲」の組を箱ごとに繰り返す。

## 経路

| 画面 | 取得 | 送信 |
|---|---|---|
| 復旧キー | `GET /api/auth/account/recovery-key` | `POST` 同じURL |
| アカウント復旧 | `GET /api/auth/account/recover` | `POST` 同じURL |
| 移譲と退会 | `GET /api/auth/account/retire` | `POST` 同じURL |

`locale=ja|en|ru` を受け付ける。アカウント画面（`/api/auth/password/settings`）と、ログインの
「パスワードを忘れた場合」から入れる。画面内のAPIへのリンクは相対URLにして、Vercelの
`/backend/{dev,stg,prd}` の中継経路から外れない。`/app/...` へのリンクは配信元のSPAを指す。

画面はRustのサービスが生成する。判断（文言、退会前に移譲が必要な箱、フォームが求める操作）は
すべてRustが行い、JavaScriptは経路、検証済みの証明の差し込み、既存と同じ取引の呼び出しだけを持つ。
JSONのAPIと画面は同じ操作関数を使うため、再認証・取引・失効の処理は一つしかない。

## 安全

- 画面にスクリプトは無く、フォームの送信先は表示中のURL。CSPで `form-action 'self'`、保存禁止、リファラー無し。
- CSRF証明は本文のhidden値とCookieの照合。Bearerと端末種別の名乗りでは本文の証明を受け付けない。
- パスワードと復旧キーは描画を行うRustに渡さない。フォームの形の判断にだけ渡し、返すのは識別子だけ。
  入力欄は再表示のたびに空にし、不正な値やエラーコードは固定の文言で表示する。
- 画面の出力枠は `value="<専用の目印>"` の属性全体。引用符は常にエスケープされるため、
  メールアドレスやボックス名が出力枠を装えない。差し込むのは、サービスが生成した43文字のASCIIだけで、
  復旧キーは既存の準備処理で検証してから結び付ける。復旧キーは新しい発行応答だけに表示し、
  Rustの出力にも、Nodeのログにも書かない。GETには出さない。
- 成功画面は取引の確定前に準備する。確定後に描画の失敗で成功を失敗に見せない。
- 未ログインの画面は、プロセスごとの上限を先に数え、言語ごとの共有テンプレート（失敗は5秒後に再試行）を使う。
  上限後は画面を生成せず軽いJSONを返す。本文は16KBまで。
- 復旧の失敗（未知のアカウント、誤キー、置き換え済み、使用済み）は同じ文言になる。

## 文言と範囲

復旧キーを持つ人がアカウントへ戻るための画面で、端末内の暗号化ファイルや暗号鍵の復旧とは別であることを
各画面の末尾に表示する。本人確認前の古いメンバーしかいない共有ボックスは移譲できないため、
「メンバーを確認・除名する」（`/app/vaults/{id}/share`）と、相手が「招待」で確認コードを入力する手順を案内する。
一度に表示する箱は20件までで、移譲後に画面を開き直すと続きを表示する。

## 受入

`acceptance --lifecycle-ui-only` を、Windows/Linuxのメモリ、PostgreSQL、正式配布イメージで実行する。
実HTTPで、未ログインの拒否、3言語、CSRF、誤パスワード、キーが一度だけ現れること、再読み込みでは出ないこと、
再発行で旧キーが使えないこと、未知アカウントと置き換え済みキーの同じ応答、復旧後の旧Cookie・旧パスワード・
使用済みキーの拒否、複数箱の移譲の繰り返し、確認用メールアドレスの不一致、退会後も共有項目が残ること、
同じメールアドレスで再登録しても共有を取り戻せないこと、未ログインの画面の上限を確認する。
実画面の確認（375px幅を含む）は別に行い、API成功を画面の合格としない。
