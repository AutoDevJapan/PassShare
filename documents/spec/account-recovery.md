# アカウントの復旧キー

共有ToDo #1163 / #1174、販売条件 M5 の一部。画面・退会・端末の暗号鍵の復旧は別の受入条件として残す。

## 発行と保管

`POST /api/auth/recovery-key` にログイン中の認証と `currentPassword` を渡す。
ブラウザは既存の Cookie と CSRF ヘッダー、モバイルはセッションの Bearer を使う。
現在のパスワードを照合し、ユーザー行とセッションを再確認してから発行する。
既存の暗号学的乱数生成器で作る256ビットのキーを作成応答に一度だけ返す。
応答は `Cache-Control: no-store`。一覧・利用者情報・通常ログにキーを含めない。
DB はキーの SHA-256 の照合値だけを保持する。新しい発行は以前のキーを失効させる。
発行応答を失った場合は、ログインしたまま再発行して保存する。古い値は再取得できない。

キーはパスワードと同じ扱いで、本人がオフラインの控え等へ保管する。
メールアドレスを知るだけ、またはセッションだけでは発行できない。
通常のパスワード変更でもキーは有効なまま残る。第三者に渡った可能性があれば再発行する。
本人がオフラインに控えた復旧手段を通常のパスワード変更で失わないため、この扱いにする。
パスワード変更は漏洩した復旧キーの取消を代替しない。

## 復旧

`POST /api/auth/password/recover` に `email`、`recoveryKey`、`newPassword` を渡す。
ブラウザでは先に `/api/auth/csrf` を取得し、Cookie と CSRF ヘッダーを付ける。
既存のIP上限に数える。未知のアカウント・誤キー・交換済みキー・使用済みキーは
同じ401応答になり、正しい証明を確認する前に新しいパスワードのArgon2計算をしない。

PostgreSQLではユーザー行をロックし、検証時のパスワードの照合値とキーの照合値を再確認する。
同じ取引でパスワードを変更し、キーを消費して、全セッションとConnect認証情報を取り消す。
同時の復旧は1件だけ成功する。変更前に照合済みのログインから古いセッションを再発行できない。
成功は204で、新しいセッションは自動発行しない。改めてログインし、復旧キーを再発行する。
保存項目・共有への所属・添付はこの操作で変更しない。

## 復旧できる範囲

このキーはアカウント認証への復帰に使う。端末内の `.pbox` や、将来のクラウド暗号鍵を
復号するキーではない。本人がパスワードも復旧キーも持たない場合の復旧は提供しない。
管理者によるパスワードの任意変更、メールを名乗るだけのリセットは提供しない。

## 受入

Rustの単体検査と実API検査を追加する。実APIは再認証、交換、情報取得時の非公開、
未知アカウントと誤キーの同じ応答、ブラウザCSRF、二重使用、旧セッション・旧Connect認証・
旧refreshの拒否、新パスワードのログイン、保存後の項目全JSONの一致を確認する。
PostgreSQLではユーザー行で実際に後続処理が待つことをPIDで確認してから解放する。
実行結果は候補コミットとともにPRへ記録する。追加した検査を実行済みとは扱わない。
