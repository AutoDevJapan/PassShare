## 文書の記述方針（Gemini 3 Pro / ChatGPT 5.2 向け最適化 / SSOT）

このドキュメントは、本リポジトリにおける **「文書の書き方」の正本（SSOT）** です。
目的は、AI（Gemini 3 Pro / ChatGPT 5.2）と人間が **同じ解釈で、最短で、迷わず** Spec→実装→テストへ到達できる状態を作ることです。

---

### 0. 絶対ルール（MUST）
- **1ファイル=1目的**（混ぜない）
- **最上部に TL;DR（要約）**を置く（3〜7行）
- **SSOTリンクを必ず持つ**（Spec→実装→テスト）
- **コマンドは1行のインラインコードで書く**（例: `python scripts/ssot/validate_ssot.py`）
  - 複数行の例はあっても良いが、**正本コマンドは必ず1行インラインで併記**
- **曖昧語を禁止**（「適宜」「なるべく」「いい感じ」など）。必要なら定義する
- **矛盾を放置しない**（矛盾が出たら、SSOT側を更新してから進める）
- **（UI）デザイン画像はSpecに含めない**（更新頻度が高い前提。UI実装時は、開発者がチャットに貼り付けた画像を正本として参照する）

---

### 1. 推奨サイズ（コンテキスト長の最適化）
- **1文書の目安**: 200行以内（長くなるなら分割してリンク）
- **1セクションの目安**: 30〜60行
- **深い入れ子を避ける**（箇条書きは最大2段まで）

> NOTE: 「長文の一枚岩」はモデルが読み飛ばしやすく、差分の追跡も難しくなるため分割を優先します。

---

### 2. 推奨テンプレ構造（Spec共通）
1. **TL;DR**（要約）
2. **目的 / 完了条件**（測定可能に）
3. **スコープ / 非スコープ**
4. **仕様（振る舞い）**
5. **例外・失敗時・境界値**（必須）
6. **セキュリティ / 運用**（秘密情報、権限、ログ方針など）
7. **実装参照（正本）**（ファイル/ディレクトリ）
8. **テスト/検証参照（正本）**（コマンド/手動手順）
9. **未確定事項（質問） / TODO**（推測で埋めない）

---

### 3. リンク設計（SSOTの迷子を防ぐ）
- **Specの台帳**: `documents/spec/index.md`
- 仕様は必ず `index.md` に登録する（孤児Spec禁止）
- 参照は **相対パス**を基本とし、存在するパスのみ書く
- 参照の“種類”を混ぜない
  - 仕様: `documents/spec/**`
  - 実装: `rpa-*/**`, `scripts/**`, `.github/**`
  - テンプレ/運用: `documents/templates/**`, `documents/config/**`, `documents/setup/**`

---

### 4. コマンド記述のルール（品質ゲートと整合）
SSOTバリデータは、Spec中の「テスト/品質」コマンドの一部について **tooling設定との整合**を検証します。

- pnpm: `pnpm -C electron format:check`（script名はワイルドカード禁止）
- backend/agent: `cd backend && uv run pytest ...` / `cd backend && uv run ruff ...`
- integration: `pnpm preflight:integration` または `pnpm preflight --run-integration`

---

### 5. Gemini/GPTどちらにも効く書き方（SHOULD）
- **名詞を揃える**（同じ概念に別名を付けない）
- **決定事項と未決定事項を分離**（Decision / Open Questions）
- **条件分岐を明示**（例: “RUN_INTEGRATION=1 の時だけ…”）
- **コピペできる**形で書く（特にコマンド/手順）

---

### 6. 禁止（MUST NOT）
- “雰囲気”で読める記述（具体性がない）
- 正本が複数ある状態（Spec/実装/テストの参照が二重化）
- 参照先が存在しないリンク/パス

---

### 7. 画像の扱い（UI）
- UIの見た目は、画像に依存せず **テキスト（表/箇条書き）で再現できる要件**として記述する（例: レイアウト、コンポーネント、状態、バリデーション、文言、非活性条件）。
- UI実装時に画像が必要な場合は、開発者が **チャットに貼り付けた画像**を正本として参照する（Specに `![...](...)` を追加しない）。
- 参考資料として画像を保持する必要がある場合（例: 外部ツールの操作説明など）は、UI Specとは区別し、用途と更新責務を明確化する。

---
