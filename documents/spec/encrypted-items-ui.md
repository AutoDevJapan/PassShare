## 保持する文脈とWorker契約

親の解除画面が所有する、生きた `CloudWorker` と解除時の `OwnerContext` だけを渡す。
利用者ID、パスワードボックスID、Workerのインスタンスを表示前に照合する。
鍵世代が変わればロックし、以前の暗号文を新しい世代とみなさない。
接続クライアントや翻訳関数を画面のキーや一覧取得の依存にしない。

親側で別途実装・統合するWorkerの契約は次のとおり。

```ts
type ItemContext = {
  passwordBoxId: string;
  itemId: string;
  itemVersion: number;
  keyEpoch: number;
};
createItem(completeFormValuesJSON: string): Promise<string>; // full envelope JSON
editItem(originalFullItemJSON: string, completeFormValuesJSON: string,
         nextItemContext: ItemContext): Promise<string>; // full envelope JSON
decrypt(envelopeJSON: string, expected: ItemContext): Promise<string>; // full item JSON
encrypt(itemJSON: string, expected: ItemContext): Promise<string>;
```

既存のgenerate/unlock/wrap、ready/closedと寿命の契約は維持する。
項目の操作ではWorkerの解除世代を変えない。
本変更はWorker・WASM・Core・バックエンドを変更しない。
基点8d6ababにない項目メソッドと `ItemContext` は、親の統合後に使用可能になる前提で直接参照する。
不足を型の強制変換や別の暗号処理で隠さない。

## 暗号文の通信

既存 `authFetch` のセッションCookie・CSRFを使う。Connectトークンと旧平文APIは使わない。
契約は [暗号文保存API](encrypted-storage-api.md) と
[RustセッションSDK](encrypted-session-client.md) に合わせる。

| 操作 | 要求 | 成功条件 |
|---|---|---|
| 一覧 | GET `/api/encrypted/boxes/:boxId/items`、任意の `?after=:cursor` | 200、最大100件の `{itemId,itemVersion,keyEpoch}` と `nextCursor` |
| 取得 | GET `/api/encrypted/boxes/:boxId/items/:itemId` | 200、Coreの全暗号文JSON |
| 保存 | PUT 同上、`{expectedVersion,envelope}` | 200、送信した全暗号文と一致 |
| 削除 | DELETE 同上、`{expectedVersion,keyEpoch}` | 204、公開された応答本文が空 |

IDは26桁の英小文字・数字、版と世代はJavaScriptの安全な正整数。
新規保存は期待版0と送信版1。編集は元の期待版と次版を使う。
公開フィールドの必須・余分なフィールド・形式・数値・canonical Base64を検査する。
一覧のIDは厳密な昇順で、100件のページだけ最後のIDと一致するカーソルを要求する。
全ページを順番に取得し、重複IDと循環カーソルを拒否した後、各項目を順番に取得・復号する。
複数のWorker要求を並行して送らない。
期待文脈は保持中のボックス・世代と、独立した一覧のID・版から作る。
GETのenvelope.contextから期待文脈を作らない。
新規IDはcreateItemのRust出力を使用し、保持中のボックス・世代と版1へ照合する。
AEAD認証と全DTOの検査はWorker/Coreが担う。

新規通信の成功本文は1.5MiB、エラー本文は64KiBまでストリームで読む。
エラーには状態番号と既知の公開コードだけを保持し、相手のメッセージや本文を表示しない。
JSON.parseによる読取りはJSON内の重複キーを検出するパーサーではない。
HTTP 204の本文はブラウザーのFetchが公開する範囲だけ検査できる。
生のHTTP不正本文をすべて検出した証拠にはしない。

## 全項目の保持と保存の再送

復号した全JSON文字列を項目ごとに保持し、表示には既存のdisplay helperと
`formValuesFromItem` だけを使用する。表示用の抜粋や旧create bodyを保存しない。
編集では元の全JSON、全フォーム値、次版の文脈をRustへ渡す。
未知フィールド、複数URL、添付情報、配列順、purposeのない隠しフィールド、任意のnullを
保持する処理は親のRust editItemが担う。タイトルだけの変更でこれらが残ることは未検証。

送信は同期したbusyフラグと単一実行関数で多重起動を止める。
1回の保存意図で生成した暗号文・ID・期待版を準備済み操作として保持する。
不明な保存結果ではフォームを固定し、利用者の明示再送で同じPUTだけを使う。
200の全暗号文一致とその復号後に、既知の次版を一覧へ反映し、次の編集を許す。
DELETEにも最初の版・世代を保持する明示再送を用意する。
自動の変更再送・再暗号化・新規IDの作り直しはない。

409では公開されたボックス状態と世代だけを確認する。項目を取り直して下書きを上書きしない。
元の全JSON・版・準備済み暗号文・フォーム値を残し、
「他の人が更新しています。下書きは保持されています。」と日英露で表示する。
明示キャンセルが下書きを破棄し、その後に一覧を読み直す。
結果不明のキャンセルも平文の下書きを破棄するが、準備済み操作は残す。
同じ操作の確認が終わるまで、新しい内容を保存する操作を止める。
確定した4xx拒否では同じ暗号文の再送を止め、キャンセル後の再読込みを可能にする。
401・403・世代不一致、または409で状態を確認できない場合はロックする。

## 寿命と互換経路

平文は解除中のReact画面のメモリーだけに置く。
保存先・localStorage・URL・consoleへ項目平文を渡さない。
ロックのグローバル通知、非表示、ページ離脱、Worker終了、アンマウント、利用者・ボックス・Worker変更で
一覧、フォーム、元JSON、表示切替、検索、準備済み操作への画面の参照を消し、要求をAbortする。
非同期の完了後は毎回、利用者の文脈と要求の生存を確認する。
古いHTTP応答が画面の内容や成功状態を戻すことを防ぐ構造であり、実際の競合試験は未実施。
JavaScript文字列とブラウザー全体のメモリーを完全に消去できるとは保証しない。

CloudBoxGateは同じ利用者・ボックスの公開メタデータ更新中に既存の暗号化画面を保持する。
一度暗号化を観測した文脈では、404から旧経路の照会へ進まない。
確認の失敗・互換モードへの逆戻り・鍵世代変更ではロックして内容を隠す。
暗号化をまだ観測していない場合の既存の互換判定・旧項目経路は保持する。
機能無効時も、旧メタデータAPIの暗号化境界の確認前に旧項目を要求しない。

### 親側に残る接続更新と操作確認

基点の `useAuthSession.refreshConnect()` とrefreshは、同じ利用者でもinvalidate(false)から
`lockCloudUi()` を同期で呼ぶ。認証フックは今回の変更範囲外なので変更していない。
本画面はこの通知を無視しないため、その経路の接続更新では解除状態と下書きが消える。
同じ利用者の接続更新で解除状態・下書きを維持するには、親が認証フックで通知の条件を分け、
利用者変更・ログアウト・失効時の同期ロックと既存のログアウト遷移対策を保持する必要がある。
基点の解除画面には独立したアイドルタイマーもない。親の既存ロック通知へ接続する範囲であり、
アイドル期限の製品仕様を今回新設していない。
