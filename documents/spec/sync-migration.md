## 移行 (#101 / #102)

2026-10-04 の保存の補足: Web の編集は、読み込んだ項目の追加フィールド・識別子・メタデータ・複数 URL を保持する。編集開始時の `version` を PUT へ送り、変更済みなら 409 で拒否する。PostgreSQL は PUT/PATCH の読み取り時の版に対して条件付き UPDATE を行い、同時保存で先の更新を失わない。`version` を省略する旧クライアントは互換性のため受け付けるが、編集開始時からの競合検出は版を送るクライアントだけで保証する。

保存と削除の失敗を画面に表示し、保存失敗時はフォームの入力を残す。読込中・保存中の二重操作と、不完全な一覧からの CSV 出力を防ぐ。CSV は平文で、追加フィールド・添付・複数 URL 等をすべて保全するバックアップではない。出力前に確認し、完全な端末バックアップは .pbox のコピーを使用する。

アカウント・招待・ボックス作成等の変更処理は、ゲートウェイの 502/503/504 応答でも自動再送しない。応答の失敗だけでは保存されていないとは断定できない。読み取りのみ再試行し、作成後の一覧は更新した権限で再取得する。遅れて返る古い一覧で新しいボックスを隠さない。

項目画面の「一覧を更新」は接続の期限と権限も取り直す。同じアカウントで接続や表示言語が変わっても、入力中のフォームと編集開始時の版は保持する。アカウントまたはボックスが変わった場合は入力と項目を消し、以前の非同期結果で別の利用者の画面を更新しない。

1PUX の取込では、抽出した全項目を変換し、入力を検査してから保存を開始する。不正なカテゴリ等で入力検査が失敗した場合は、先行項目も保存しない。保存は行単位なので、途中失敗時は一部だけが保存される。同じアカウント・Box・元ファイル・取込試行のキーを保持して再送すると、確定行は同じキーで照合し、新しい作成を重ねない。変更・削除済みの確定行は再作成せず部分結果として扱い、未完了行を元キーで継続する。認証・暗号化境界の拒否は変更済み扱いで通過させない。

WebのCSV再試行記録は本文を含まない行キー・完了位置等をbrowser session内に保持する。Webの1PUX取込キーも同じbrowser session内の記録を使う。Desktopの1PUX試行キーはprocess内で保持するため、browser session終了・Desktop再起動をまたぐ再取込の重複防止まで保証しない。完全終了後の新しい取込は別試行であり、同内容の正当な別項目を排除しない。元データは件数・内容の確認が終わるまで保持する。

公式1PUXのaccount/vault/item階層とDocument添付は、documentIdでZIP内の一意な実体を参照し、表示名を別metadataとして保持する。内部binary名と表示名の一致は要求しない。項目とその添付は同じPostgreSQL transactionで確定し、再送では添付bytesも照合する。全カテゴリ・custom icon・全添付表現の完全対応を意味しない。添付の取込上限と暗号化移行の上限も異なり、既存移行validatorは1添付1MiB超を拒否する。検証範囲は[取込の検査記録](../audits/2026-10-05-import-validation.md)を参照する。

WebのConnect互換一覧は対応backendのmetadataで表示・検索し、編集とコピー時に現在資格で対象詳細を取得する。秘匿本文は一覧previewへ出さず、コピー可否だけを返す。通常のsecure note previewは既存カードに必要な先頭81文字までであり、一覧応答も権限対象データとして扱う。旧backendでmetadataが無い場合は詳細取得へfallbackする。CSV出力とDesktop完全同期は全詳細を順序保持で取得し、同時8件に制限する。一覧metadataを完全な同期データやバックアップに置き換えない。

| 1PUX インポート | Connect API | Connect API |
| 1Password CSV エクスポート | `.pbox` → ファイル保存 | ブラウザダウンロード |

### Web CSVのレコード解析

Web取込は引用内のLF/CRLF・カンマ・二重引用符をレコードの一部として保持し、
既存CSV出力からのLogin値を往復できる。本文セルは前後空白も値として保持する。
headerの正規化と、Title/Passwordが空の行を取込対象外とする既存条件は維持する。
引用未終端・非引用セル途中の引用符・閉じ引用符後の不正文字は、全レコードの
変換が終わる前に拒否し、先行行も保存しない。空fieldと正当な同内容別行を排除しない。
これはCSVが扱うLogin列の完全性であり、1PUX・添付・全カテゴリの完全取得ではない。
既存exportの数式無害化prefixは解除せず、その仕様も変更しない。
非引用のCR/LF/CRLFはレコード区切りとする。Title/Passwordの空白のみ判定は従来どおり取込対象外だが、有効な値の前後空白は除去しない。

上記の値保持はCSV解析時の契約であり、保存用変換で既存のURL前後空白除去とtagsのカンマ分割・要素trimは維持する。URL内部の文字・percent encodingやnotes/username/passwordの内容をこの正規化で変えない。CSVのtags列は元からカンマを含む単一tag等を完全往復する形式ではない。

DesktopのRust CSV取込もheaderのみを一律trimし、password/username/notesの有意な前後空白と引用内改行を暗号化保存・再open後も保持する。必須欄の空判定とURL/tagsの既存正規化は値保持と分離する。
