# 端末の変更と保存の確定

ToDo 1197・1176、監査 M6 の保存失敗を扱う。画面の形は変更しない。

以前のデスクトップは項目の作成・編集・削除・CSV取込・クラウド同期をメモリへ反映した後に保存していた。保存失敗を表示しても変更が残り、再試行で二重作成したり、後の成功した保存で失敗した削除まで確定したりする経路があった。ファイルだけの原子的な置換では、このメモリの不整合は防げない。

Rust Core の `SavedChange` と `PasswordBox::apply_and_save` は、変更を別の状態へ適用する。検証と既存の暗号化・一時ファイル・同期書込・置換が成功した後に、その状態を公開する。更新・削除・同期で項目を取り除く前にも全フィールドの値を消去し、残るコピーは既存の終了時の秘密値消去処理を通って破棄する。デスクトップの5経路はこの処理を共用する。未保存の編集を意図的に組み立てる既存 Core API は維持する。異常終了全般で秘密値消去を保証するものではない。

受入条件:

- 作成・編集・削除・CSV取込・同期のそれぞれで、実ファイル置換を失敗させる。項目全体、パスワードボックスの件数・時刻、元の暗号化バイトが変わらず、一時ファイルも残らない。
- 保存先を復旧して一回再試行する。成功した内容が再読込で一致し、作成とCSV取込は一回分だけ増える。同期の既存ID更新と新ID追加を両方確認する。編集と同期は非表示の情報を含む元の項目を保持し、削除は成功後にだけ反映される。
- 存在しない項目の更新と施錠後の変更は、ファイルを書かずに拒否する。
- 更新・削除・同期で取り除くコピーのフィールド値を、解放前の有効な参照で観測する。観測に残すのはIDと「全値が空」の真偽だけで、解放済みメモリと実ユーザーの値を読まない。
- 保存前にメモリへ公開する回帰を検証用パッチで入れると、5経路の6検査がすべて失敗する。検証拒否と秘密消去の2検査は成功する。パッチを戻して全Core検査を通す。WindowsとLinuxで実行し、既存のDocker検査とデスクトップの検査・ビルドも通す。

初回の別モデルレビューは秘密消去の抜けをMust、新ID同期の検査不足をSuggestionとして指摘した。両方を修復した。初回CIではLinuxのCore全54検査が成功し、保存前の公開を戻した5検査が失敗した。その後のlintは既存のnonce変換が非推奨で停止したため、警告を許容せず固定長配列からの変換へ修正した。[型の公式仕様](https://docs.rs/hybrid-array/0.4.13/hybrid_array/struct.Array.html#impl-From%3C%5BT;+N%5D%3E-for-Array%3CT,+U%3E)に従い、暗号方式・nonceの長さ・ファイル形式は変えない。修復後の結果は同じ候補の実検査で確認する。

これだけで M6/M7 全体を完了としない。クラウド取得時の完全な情報保持、背景・アイドル終了、マスターを失った場合の実復旧、旧形式、署名と各端末の導入・更新・削除は別の受入として残る。クラウドのクライアント暗号化と、現在の本人資格の照合もこの処理の証明には含めない。
