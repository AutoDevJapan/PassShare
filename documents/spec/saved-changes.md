# 端末の変更と保存の確定

ToDo 1197・1176、監査 M6 の保存失敗を扱う。画面の形は変更しない。

以前のデスクトップは項目の作成・編集・削除・CSV取込・クラウド同期をメモリへ反映した後に保存していた。保存失敗を表示しても変更が残り、再試行で二重作成したり、後の成功した保存で失敗した削除まで確定したりする経路があった。ファイルだけの原子的な置換では、このメモリの不整合は防げない。

Rust Core の `SavedChange` と `PasswordBox::apply_and_save` は、変更を別の状態へ適用する。検証と既存の暗号化・一時ファイル・同期書込・置換が成功した後に、その状態を公開する。失敗した変更と以前の状態は既存の秘密値消去処理を通って破棄する。デスクトップの5経路はこの処理を共用する。未保存の編集を意図的に組み立てる既存 Core API は維持する。

受入条件:

- 作成・編集・削除・CSV取込・同期のそれぞれで、実ファイル置換を失敗させる。項目全体、パスワードボックスの件数・時刻、元の暗号化バイトが変わらず、一時ファイルも残らない。
- 保存先を復旧して一回再試行する。成功した内容が再読込で一致し、作成とCSV取込は一回分だけ増える。編集と同期は非表示の情報を含む元の項目を保持し、削除は成功後にだけ反映される。
- 存在しない項目の更新と施錠後の変更は、ファイルを書かずに拒否する。
- 保存前にメモリへ公開する回帰を検証用パッチで入れると、5経路の検査がすべて失敗する。パッチを戻して全Core検査を通す。WindowsとLinuxで実行し、既存のDocker検査とデスクトップの検査・ビルドも通す。

これだけで M6/M7 全体を完了としない。クラウド取得時の完全な情報保持、背景・アイドル終了、マスターを失った場合の実復旧、旧形式、署名と各端末の導入・更新・削除は別の受入として残る。クラウドのクライアント暗号化と、現在の本人資格の照合もこの処理の証明には含めない。
