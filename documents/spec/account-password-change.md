# アカウントのパスワード変更

共有ToDo #1163 / #1174、M5 の一部。共有本人確認PR #607 の後に統合する。
アカウント認証のパスワードを変更する機能であり、端末の `.pbox` のマスターパスワードや
端末間暗号化の鍵を変更する機能ではない。

## API

`POST /api/auth/password/change`。現在のセッションとCSRF保護、現在のパスワードを要求する。
本文は `currentPassword` と `newPassword`。本人のユーザーIDはセッションから決め、指定できない。
成功時は204を返し、WebのCookieを消去する。Mobile/Extensionは旧認証情報を破棄して再ログインする。
Connectのアクセストークン単独では変更できない。

Rustは型・長さ・同じパスワードの拒否、コミット時の確認済み認証情報と現在の状態の一致を判定する。
Argon2idの検証・ハッシュ生成は既存の接続を再利用する。新しいパスワードは8文字以上・1024バイト以下。
現在のパスワードは既存の登録・ログインの長さ契約を保持する。旧来の長い値も変更できる。
ログインと同じIP上限・失敗ロックを使う。Rustへの入力は標準入力で渡し、応答には操作の種類だけを返す。
値・ハッシュ・認証情報をログやエラー応答に含めない。

## 取引と競合

PostgreSQLはユーザーの行、次にセッションの行をロックする。
検証時のハッシュが現在の値と一致し、現在のセッションが残っている場合だけ変更する。
パスワード更新、全セッションの削除、全Connect認証情報の削除は一つの取引で確定する。
失敗時は元のパスワード・セッション・項目を保持する。

ログインのセッション作成は、確認したハッシュを条件にユーザーの行を共有ロックする。
Connect認証情報の発行は、同じ行の共有ロックと現在のセッションを要求する。
変更より前に発行が確定した場合は変更時に削除する。
変更より後に古い検証結果やセッションで発行しようとした場合は拒否する。
メモリ保存でも検証中の利用者をコピーし、非同期処理の後に現在の値を再照合してから一括変更する。

## 受入

Rustの判定試験と正式APIで、未ログイン・誤った現在のパスワード・同じ値・旧セッション・
旧Connect認証の拒否、新しいパスワードでの再ログイン、ボックスの保持を確認する。
PostgreSQLでは変更をロックで保持し、古いパスワードのログインと認証情報更新の両方が
そのPIDにブロックされていることを確認してから解放する。
変更後に旧セッション・認証情報が一つも作り直されていないことを直接照合する。
Windows/Linux・メモリ/DB・正式配布イメージで実行する。成功は結果を得てから記録する。
