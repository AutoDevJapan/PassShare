# アカウントのパスワード変更

共有ToDo #1163 / #1174、M5 の一部。共有本人確認PR #607 の後に統合する。
アカウント認証のパスワードを変更する機能であり、端末の `.pbox` のマスターパスワードや
端末間暗号化の鍵を変更する機能ではない。

## API

`POST /api/auth/password/change`。現在のセッションとCSRF保護、現在のパスワードを要求する。
本文は `currentPassword` と `newPassword`。本人のユーザーIDはセッションから決め、指定できない。
成功時は204を返し、WebのCookieを消去する。Mobile/Extensionは旧認証情報を破棄して再ログインする。
Connectのアクセストークン単独では変更できない。

Rustは型・長さ・同じパスワードの拒否、コミット時の確認済み認証情報と現在の状態の一致を判定する。
Argon2idの検証・ハッシュ生成は既存の接続を再利用する。新しいパスワードは8文字以上・1024バイト以下。
現在のパスワードは既存の登録・ログインの長さ契約を保持する。旧来の長い値も変更できる。
ログインと同じ共有IP上限・失敗ロックを使う。認証のDB照合より前にも、同じ上限の標準middlewareを接続する。
後者は各プロセス内の軽い防御で、共有・再起動後の制限を代替しない。
Rustへの入力は標準入力で渡し、応答には操作の種類だけを返す。
値・ハッシュ・認証情報をログやエラー応答に含めない。

## 取引と競合

PostgreSQLはユーザーの行、次にセッションの行をロックする。
検証時のハッシュが現在の値と一致し、現在のセッションが残っている場合だけ変更する。
パスワード更新、全セッションの削除、全Connect認証情報の削除は一つの取引で確定する。
失敗時は元のパスワード・セッション・項目を保持する。

ログインのセッション作成は、確認したハッシュを条件にユーザーの行を共有ロックする。
Connect認証情報の発行は、同じ行の共有ロックと現在のセッションを要求する。
変更より前に発行が確定した場合は変更時に削除する。
変更より後に古い検証結果やセッションで発行しようとした場合は拒否する。
メモリ保存でも検証中の利用者をコピーし、非同期処理の後に現在の値を再照合してから一括変更する。

## 受入

Rustの判定試験と正式APIで、未ログイン・誤った現在のパスワード・同じ値・旧セッション・
旧Connect認証の拒否、新しいパスワードでの再ログイン、ボックスの保持を確認する。
PostgreSQLでは変更をロックで保持し、古いパスワードのログインとConnect認証情報の直接発行の両方が
そのPIDにブロックされていることを確認してから解放する。
変更後に旧セッション・認証情報が一つも作り直されていないことを直接照合する。
Mobileの認証情報更新も同時に要求し、変更後に拒否されることを確認する。
初回試験は、更新がセッションの行で先に待つ点を考慮せず、ユーザーの行での待ちを二つ要求したため失敗した。
待ちの確認を弱めず、直接発行を別に重ねてユーザー行での競合と更新の拒否を分けて検証する。
Windows/Linux・メモリ/DB・正式配布イメージで実行する。成功は結果を得てから記録する。

## 承認されたWeb画面

2026-10-05T23:21:49.018000+00:00（日本時間2026-10-06 08:21:49.018）の
オーナー投稿1556808661542637569「a」は、スレッド1556698757096145046の
パスワード変更画面案で進める回答として反映する。この承認は他の新しい画面案には適用しない。

Webの「アカウント」から `GET /api/auth/password/settings` を開く。
既存のRustサービスが日本語・英語・ロシア語のHTMLを生成する。
現在のパスワード、新しいパスワード、確認用の新しいパスワードを入力する。
`POST /api/auth/password/settings` のフォーム本文にCSRF証明を含め、Cookieと照合する。
この経路だけフォームを受け付け、JSONの変更APIでは本文のCSRF証明を受け付けない。
確認用の値の一致と既存の入力条件をRustで判定し、既存APIと同じ変更取引を実行する。

成功画面は取引の確定前に準備する。確定後はCookieを削除し、再ログインへのリンクを表示する。
画面は保存を禁止し、フォームの送信先を同じ配信元に限定する。
大文字や末尾スラッシュのあるURLでも同じ確認を強制する。
フォームの送信先は表示中のURLとし、Vercelの `/backend/dev`・`/backend/stg`・
`/backend/prd` の中継経路を保持する。APIの絶対パスへ送ってSPAへ戻ることを防ぐ。
未認証の本文は解析せず、未ログイン・不正なCookie・期限切れは共通の再ログイン画面を使う。
GETとPOSTは別の上限で制限する。上限後の応答は画面生成のプロセスを起動しない。
未認証画面の生成中は同じ要求を共有し、一時失敗は5秒待ってから再試行できる。
失敗画面へ入力したパスワードを戻さず、既知のエラーを選んで翻訳する。
Webへ戻る配信元は既存の許可規則で照合し、不正な外部URLへのリンクを作らない。
秘密値をURL・HTML・エラー本文へ含めない。スクリプト、追加サービス、追加費用は不要。

Rustの実API受入へ、HTML配信・確認不一致・誤った現在の値・フォームCSRF拒否・
JSON APIでの本文CSRF拒否・全Cookie削除・旧Connect認証拒否・旧値拒否・新値でのログインを追加する。
既存のメモリ保存、PostgreSQL、正式Dockerイメージの受入と一緒に実行する。

Web画面と変更APIは実装済み。Rust34件、Windows/Linuxの実メモリAPI、
PostgreSQLと正式Dockerイメージで、確認不一致・CSRF・変更と失効・新しい値のログインを検証した。
Chromeで承認案に沿う実画面と375px幅の横はみ出しなしを確認した。
一時的な生成失敗503、待機中503、5秒後の再ログイン画面401への復旧も確認した。
別モデルの修復後レビューは必須指摘0件。全候補のCIとmainへの統合はPR #639で確認する。
