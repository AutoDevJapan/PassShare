# 既存クラウドの暗号化移行API（有限の受入）

元1163のM4-Cのうち、所有者1名だけが所属し、招待がない既存の互換クラウドのパスワードボックスを対象とする。Core契約は `encrypted-migration-core.md`。他の利用者への鍵配布、画面、SDKへの移行入口追加、WASM、全クライアント、`.pbox`・CSV・1PUXの解析はこの成果に含めない。未回答の画面からの鍵配布の判断をこのAPIで置き換えない。

## 認証と移行元の完全性

正式なNode入口から既存セッションで認証する。cookieには既存CSRF検査を適用し、全応答はno-store。Connectトークンでは移行できない。所有者であること、所属が1名であること、招待が0件であることをDBのロック後に毎回調べる。

`GET /api/encrypted/boxes/:boxId/migration-source` はDBが管理する正の `sourceRevision`、全項目数、全添付数を返す。呼出元の整数や平文ハッシュを状態の証明として採用しない。次の所有者専用の読取はこの版を必須とする。

- `/migration-source/items?revision=N&after=ID`：ID順で最大100件のIDと保存された項目版。最終ページはafter=null。実在しないカーソルと古い版は409。
- `/migration-source/items/:itemId?revision=N`：保存された完全JSON。未知属性、URLの追加属性、配列順、null、版を型付きDTOに変換せず返す。
- `/migration-source/items/:itemId/files/:attachmentId?revision=N`：メタデータと、存在する場合のBase64本文。`available=false, content=null` は本文がないことを意味する。長さ0の実本文は `available=true, content=""`。

全添付参照は保存されたファイル行と1対1で一致する必要がある。参照ID・正の版・元世代・所属・任意の名前と長さを検査する。欠落・余分・同一IDの重複・曖昧な古い参照を拒否する。添付参照がない項目は添付0件。参照のnullを空配列にしない。互換ストアに項目の鍵世代列はないため、呼出元は元contextの世代を添付参照と整合するよう独立して供給する。添付のない項目の元世代は、呼出元が保持する元contextの値であり、サーバーで旧暗号鍵が実在すると主張しない。

`encrypted_migration_sources` は平文を持たず、項目・ファイル・所属・招待・パスワードボックス属性の変更をDBトリガーで数える。削除後の再挿入でも版を戻さない。所有者の認証用ユーザー行のダイジェストも現在値と照合する。これは認証の変更検出用であり、移行元の項目・ファイル本文のハッシュではない。復元によって物理xminが変わっても、同じ認証状態なら一致する。

## クライアントの準備・仮置き・確認

所有者のクライアントが実バイトを信頼した元データまたは保管済みファイルから取得する。互換ストアにメタデータしかない場合、サーバーは本文を発明できない。対応する全ファイルの実バイトを確保し、Coreで暗号化して仮置きし、所有者bundleから復元した同じ鍵で仮置き応答を読み戻して全JSON・名前・全バイトを独立した元データと比較する責任はクライアントにある。

サーバーはAEADや暗号文内部の参照を認証できない。同じ公開contextを持つ間違った鍵・本文の暗号文を、ヘッダーだけで見破れるとは主張しない。全件数と公開対応の検査は、このクライアント検査の代わりではない。読み戻しに失敗したクライアントは確定せず、取消して元を保持する。

Core `prepare_migration` の安定した `replay_bytes()` を保持する。operation IDを使い回してprepareをやり直さない。送信時は計画を次の有限の部分に分ける。サーバーはJSON値として同じ公開対応・nonce・暗号文を厳密比較する。HTTP JSONの空白・属性順を復元する契約ではない。移行元と先のパスワードボックスIDはこの有限APIでは同じ。先の所有者contextと全暗号文の世代は1。項目IDは明示した対応で変更可能で、版は元の17など正の値を保持する。

- `PUT /migrations/:operationId`：Core計画からitemsを除いたformat、operationId、ownerContext、sourcePasswordBoxId、sourceRevisionに、itemCount、attachmentCount、ownerBundleを付ける。bundleは準備に使った同じ鍵を所有者のroot keyで包む。生の鍵・パスワードは送らない。
- `PUT /migrations/:operationId/items/:targetItemId`：Core項目のbindingとenvelope。元添付参照の順序と各contextを照合する。
- `PUT /migrations/:operationId/items/:targetItemId/files/:targetAttachmentId`：対応するCore添付を `{envelope: ...}` で送る。名前は暗号文内のみ。
- 上記項目・ファイルへのGET：保存した暗号文を所有者に返す。確定前のCore復号・独立したexpectedによる参照検査に使う。
- `GET /migrations/:operationId`：status、expired、保存したheader。応答喪失時はこれを確認してから同じ計画を明示的に再送する。
- `DELETE /migrations/:operationId`：未確定計画を取消し、仮置き行を除去する。元の全行は変更しない。同じIDは別計画に再利用できない。

仮置き期限は開始から30分。同一の再送で期限を延長しない。同じパスワードボックスの未確定計画は1件。次の計画の開始には、古い計画を明示的に取り消す。期限・元状態・認証が変わった計画の仮置き・確定を拒否する。所有者は現在の認証で状態を確認し、取消せる。

先IDを変更する場合は、別の元項目・元添付のIDと交差しない新しいIDにする。A→B、B→Cや添付IDの交換を拒否し、同じIDを別の元データへ再束縛しない。変更した元項目IDと元添付IDは既存の削除記録に正の元版を保持して予約する。

## 一括確定と失敗

`POST /migrations/:operationId/commit` は本文なし。DBの一つの取引で、パスワードボックス→ユーザー→セッション→所属・招待→元状態・計画→確定対象行をロックする。待機終了後の実時刻でセッションの有効性を確認する。全元ID・保存された正の版・全添付・現在の所有者・認証状態・元世代との対応・期限・owner bundle・先世代・全件数を再検査する。

成功時だけ、暗号化状態・所有者bundle・項目・全添付をまとめて公開し、元ファイル・元項目と平文を持つ旧作成再送記録を除去する。IDを変更した元項目は既存の削除記録で予約する。パスワードボックスの名前・説明など既存の公開メタデータは残る。認証用の既存password_hashも認証のため残る。項目本文・ファイル名・ファイル本文・クライアント暗号鍵をこれらに残す経路は追加しない。MVCCの古いページ、WAL、移行前のバックアップの物理消去をこの取引の成果とは主張しない。

制約・障害・認証失効・元変更・不足は成功を返さず、元の全行とxminを保持する。旧項目・ファイルの書込も同じ親行をロックし、暗号化状態への切替を確認する。暗号化HTTPの機能フラグを切ってもDBの境界は残る。変更途中のトリガーや直接SQLとロック順が競合した場合はDBが取引を中止できるが、途中の暗号化状態を成功として公開しない。

確定済み操作のstatusと明示的なcommit再送は、現在認証された所有者にcommittedを返す。header・項目・ファイルの再送は保存した同じ内容のみ成功し、新しいnonceや暗号文は409。既存の項目・添付の削除と鍵更新のCAS入口を変更しない。

## 上限・復元・検証

Coreと既存サーバーの上限を使う。項目暗号化平文1MiB、添付本文1MiB、名前4096 UTF-8 bytes、全添付1024件、全項目暗号化平文＋全添付本文＋全名前1GiB。サーバーでは暗号文の復号前長さから集計し、超過した仮置きを同じ取引で取り消す。HTTPは既存の2MiB入口で1項目または1ファイルずつ送る。正の版・世代・状態版は9007199254740991以下。JSONの重複属性と浮動小数点の版はRustで拒否する。

新しい4表（sources、migrations、items、files）はpublicの全表ダンプに含める。復元の既知表一覧と、現在の認証状態との一致検査にも追加する。仮置き中と確定済みの両方を別の所有・用途印を持つ空DBへ復元し、全public行の意味上の一致と元DBの全行・xmin不変を検査する。復元DBは親DBや本番DBを上書きしない。
