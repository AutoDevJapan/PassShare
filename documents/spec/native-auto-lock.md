# デスクトップの放置期限による施錠（1197 / 1176）

Rustが単調時計で最後の利用者入力から5分の期限を管理する。一覧取得や同期などの自動処理では期限を延長しない。再起動時は施錠状態から始める。既存の画面と認証を使用する。

暗号化ボックスの秘密消去、期限判定、全項目の読取・検索・CSV出力・保存の拒否は、単一の状態と同じ排他区間で処理する。期限切れ後の入力も再び開くことはできない。UIのpollが止まっても本体のタイマーが秘密を消去する。

Rustの世代番号を開く成功・手動終了・期限到達で更新し、イベント・成功時の状態確認・pollを同じ番号で照合する。遅い古い結果を捨て、素早い開き直し後の次の終了も画面へ反映する。現在の画面が保持するパスワード、一覧、編集・同期設定は画面を破棄して消去する。破棄済みSetupPanelの古い認証結果は親状態へ書き戻さない。

```gherkin
Given 開いたパスワードボックスと画面の秘密入力・項目一覧
When 5分間入力せず一覧を自動取得する
Then 期限で本体と画面の秘密を消去し全秘密IPCを拒否する
And 再認証後は原ファイルの内容が完全に一致する

Given 手動終了したパスワードボックス
When 次のpollより前に再認証してもう一度終了する
Then その新しい世代の画面も秘密を消去する

Given 期限直前の開いたボックス
When 前景で実際に入力する
Then 入力から5分に期限を更新する
And 期限切れ後の入力では施錠を解除しない
```

検証はRustの境界・世代3試験と本体2受入、実LinuxTauriの画面を開いて非空秘密入力・一覧を確認した後の手動終了2回と本番5分、秘密IPC拒否、原暗号化バイト・再認証後の全内容一致を含む。期限と手動世代照合を外した版は3件とも失敗させる。

背景移行による即時施錠と、Mobileの背景・放置施錠は未実装のまま1176で継続する。固定生体認証0.2.8の公開APIはWindowsの認証に親ウィンドウを渡さず、macOSの資格読出しに呼出元管理の認証contextを渡さない。そのためOS認証画面のblurを実背景と判別できるバックエンドが必要になる。全blurを無条件に拒否して正常な生体解除を壊す案は採用しない。

恒久対応では、認証試行をRustで開始し、資格をRust内で開いて消去し、OS側の取消しと真の背景移行を同じ世代で管理する。Windowsのparent HWND/foreground監視とmacOSのLAContext取消しを実OSで受け入れる。MobileのPIN/生体認証と資格読出しも一つの試行にまとめ、古いlogin/refreshの保存・削除を世代付きで直列確定する。署名配布・緊急復旧・全22受入・販売完了は本修正だけで完了にしない。
