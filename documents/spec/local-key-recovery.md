# 端末内のパスワードボックスの復旧

共有 ToDo 1163 / 1176、M6-B の Rust Core 実装仕様。アカウントの復旧とは別の機能である。
この仕様は端末内の `.pbox` と架空データの検証を対象とする。画面・SDK・クラウドへの接続、
製品全体の受入、販売の承認は含まない。

## 保存方式と互換性

新規作成は暗号ラッパー version 2。本文の形式を表す `payloadVersion` とは区別する。
本文は従来どおり、マスターパスワードと Argon2id から得た 32 バイトの鍵で
XChaCha20-Poly1305 により一度だけ暗号化する。本文を複製しない。

version 2 は `recovery` に別の XChaCha20-Poly1305 暗号文と nonce を持つ。
この暗号文は本文鍵の 32 バイトを封じたもの（認証タグ込み 48 バイト）である。
鍵には OS の乱数から生成した 256 ビットの復旧コードを直接使用する。
入力形式はパディング付きの標準 Base64 を正規化した 44 文字で、空白や省略形式は受け付けない。
復旧コードを知らなければ、ヘッダーだけから本文鍵を得ることはできない。
復旧コードはパスワードと同じく秘密として管理する。

復旧暗号文の associated data は、次を連結する。

1. 固定用途 `PassShare/pbox/recovery-master-key/v2` と末尾の NUL。
2. ファイル version の 4 バイト big-endian 表現。
3. 主暗号ヘッダーと主暗号本文の SHA-256 ハッシュ。

ハッシュの入力は `serde_json` による `(kdf, cipher)` の配列形式の直列化である。
その長さを 8 バイト big-endian で先頭に置き、続けてヘッダーのバイト列と
主暗号文のバイト列を入力する。構造体のフィールド順が直列化順となる。
KDF の方式・salt・コスト、主暗号の方式・nonce、主暗号文の全体が束縛される。
本文、ヘッダー、別ファイルの復旧暗号文を差し替えると復旧は失敗する。
通常のパスワードで開く場合も、本文内のコードで復旧暗号文を検証し、本文鍵との一致を確認する。
復旧で開く場合は本文内のコードと入力コードの一致を確認する。
本文内の `localKeyRecoveryVersion: 2` も照合する。ヘッダーの version を 1 に変更して
復旧暗号文を削除しても、暗号化本文に残る値との不一致により通常の読み込みを拒否する。

version 1 は引き続き読める。通常の `save` では version 1 を維持し、復旧を勝手に有効化しない。
version 1 の本文にコードが記録されていても、明示的に有効化するまでは復旧に使えない。
従来の version 1 アプリは version 2 を `CorruptFile` として拒否するため、
復旧情報を無言で落として通常保存することはない。

ヘッダーとその子構造体では未知フィールドを拒否する。
version 1 に復旧暗号文がある場合、version 2 に復旧暗号文がない場合、
未知の version / 暗号方式、salt / nonce の長さ不一致、復旧暗号文の長さ不一致も拒否する。
Argon2id の受入範囲はメモリ 19,456〜262,144 KiB、反復 2〜10、並列数 1〜16 とする。
通常の新規保存は従来の 65,536 KiB、反復 3、並列数 4 を使用する。
復旧の経路でも KDF の範囲を検査するが、パスワードによる導出は実行しない。

## Rust の呼び出し

`PasswordBox::create(path, master_password)` は version 2 と復旧コードを生成する。
既存の `recovery_secret()` は開いている間だけコードの参照を返す。

`enable_recovery(current_master_password)` は保存済みファイルで現在のパスワードを再確認し、
version 1 を version 2 に保存する。本文内の正規なコードを再利用し、コードがなければ生成する。
version 2 への再実行でもコードを変更しない。返り値は `Zeroizing<String>`。
失敗時はオブジェクトの version / コードを公開前の状態に保つ。

`PasswordBox::recover(path, code)` はマスターパスワードなしで開く。
この呼び出しはファイルを書き換えず、取得した本文鍵もオブジェクトに保持しない。
項目の読み取りとメモリ上の編集はできるが、`save` / `apply_and_save` は
`InvalidMasterPassword` として拒否する。復旧で開いたことによる誤保存を防ぐためであり、
保存に渡したパスワードが正しいかどうかを検査した結果ではない。

`rekey_recovered(new_password)` は復旧で開いたオブジェクトだけに使用できる。
空のパスワードは拒否する。新しい salt と新しいパスワードで本文鍵を導出し、本文と復旧暗号文を作り直す。
原本と同じディレクトリの暗号文専用一時ファイルを fsync 後、原本へ atomic に置き換える。
成功後に通常保存できる状態へ移る。失敗時には、原本とオブジェクトの salt / 状態を保持し、再試行できる。
古いパスワードは変更済みのファイルを開けない。

復旧コードは再暗号化後も再利用でき、使っただけでは消費しない。
`rotate_recovery(current_master_password)` はパスワードを再確認し、現在のファイルに新しいコードを設定する。
変更済みファイルで古いコードは使えない。古いバックアップは元の version とパスワードで開け、
復旧が有効だったバックアップは元のコードでも開ける。
現在のファイルでコードを変更しても、既に他者が持つ古いコピーへのアクセスは取り消せない。

読み込み時と保存成功時に暗号ラッパー全体の SHA-256 を記録し、置換の直前に原本と照合する。
別のオブジェクトが先に保存した場合は `CorruptFile` として上書きを拒否し、再読み込みを求める。
この確認は複数プロセス間の排他ロックではないため、同時書き込みを直列化する機構は呼び出し側に必要である。

## データと秘密の保持

認証済みJSONを借用して型へ変換し、無視された追加情報を含む一時JSONの文字列とキーを
破棄時に消去する。入力・原本・自分が所有するJSONのバッファを対象とし、serde内部の
一時割当や、メモリー全体に残るすべてのコピーを消去できるとは保証しない。

型付きの項目、URL、フィールド、項目群の属性、本文 version を保持する。
認証済みの元 JSON も `Zeroizing<Vec<u8>>` に保持し、現在の DTO で表していない
項目の追加情報、添付ファイルの参照、項目 version を保存時に合成する。
添付ファイル本体は `.pbox` に追加しない。未知項目は参照として保持するだけで解釈しない。
既知フィールドの削除と項目の削除を、元 JSON から復活させない。
従来の LoginItem 本文は既存の移行処理で型付き本文へ変換する。

本文鍵、復旧用の鍵、乱数生成途中の秘密、復号したバイト列、一時 JSON の文字列、
保持中のフィールド値とコードを所有者の drop / lock / 失敗時に消去する。
`lock()` 後は項目とコードの参照を返さない。呼び出し側が取得したコピーは呼び出し側の責任で消去する。
既存 DTO の文字列再割当てなどにより既に解放されたコピーまで消去できるとは保証しない。

## 架空データでの受入

`password_box_recovery_tests.rs` は次を検査する。

- 新規 version 2 作成、保存、再起動、パスワードなしの復旧、新パスワードによる再暗号化。
- 既知 DTO と追加 JSON・URL・添付参照・項目 version の保持、古いパスワードの拒否。
- 独立した version 1 形式の固定 fixture、version 維持、明示的な復旧有効化。
- 誤コード、別ファイルの復旧暗号文、主ヘッダー・本文・復旧暗号文の改変の拒否。
- 本文鍵と復旧鍵が同じ別ファイルからの混在、本文と入力コードの不一致、v1 への偽装の拒否。
- KDF の下限・上限、nonce・暗号方式・version・未知ヘッダー構造の拒否。
- 保存失敗時の原本のバイト列と SHA-256 の一致、再起動と再試行。
- 復旧コードの再利用・変更、古いバックアップへのアクセス、lock と drop。
- 古い読み込み状態からの保存・復旧有効化・コード変更・再暗号化による上書きの拒否。

Rust Core と依存先の関連検査、Clippy を同じ専用生成先で順に実施する。
最終 workspace 全件の検証は親担当がマージ前に一度実施する。
