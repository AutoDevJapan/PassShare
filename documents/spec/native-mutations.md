# 原本を保持する編集と作成操作の再送

関連: 製品監査M2、共有ToDo1163/1197/1482/1660、PR592。

保存問題は、表示用の投影を保存用の原本に使っていたことと、再送を別の作成として扱っていたことに分ける。新しい保存判断は `backend/native` のRustが行い、既存Node APIは認証・HTTP・DB接続を担当する。

## 編集

`PUT /v1/vaults/:box/items/:item/form` は `{ version, values }` を受け取る。認証とパスワードボックスの権限判定は既存経路を通す。APIが読み取った全JSONの原本と、編集開始時の版をRustへ渡す。版が違えば409。変更した表示フィールドだけを更新し、非表示のfields/sections/files/metadata、識別子、未編集の複数URLを保持する。保存にも既存PostgreSQLの版条件を適用するため、Rustの判定後に別の更新が入っても409となる。

WebとMobileは表示用項目とは別に編集開始時の原本と版を持つ。タイトルだけの変更で、空本文・非空本文のカードや追加フィールドを失わない。Desktopの端末保存はRustで選択されたURLだけを変更し、その他を保持する。本文のAPI表現と端末内表現は異なる。全クライアントの同期形式や暗号化・配布の完成をこの修復に含めない。

## 作成と結果不明

`Idempotency-Key` がある項目・パスワードボックスの作成は、利用者・保存先・操作種別・キーを一つの操作とする。同じキーと同じ入力は保存済み結果を照合して返す。同じキーで入力が変わった場合、結果が編集・削除された場合、権限を失った場合は競合または拒否を返し、別の作成にしない。異なるキーの同じ入力は意図的な別作成として許可する。

PostgreSQLでは操作ごとにトランザクションのロックを取り、作成した項目、またはボックスと所有者の所属、および再送記録を一括保存する。DB故障時に片方だけ確定しない。コミット後の応答消失と再起動は同じ記録へ照合する。記録には入力と結果のSHA256・対象IDのみを保存し、秘密値の二重保管を増やさない。記録はバックアップ対象となる。開発用メモリストアでは操作を直列化するが、再起動後の保持はPostgreSQLだけが保証する。

Web/Mobileは送信前に操作キーを用意し、失敗・言語変更・資格の再取得をまたいで保持する。成功、別利用者・別ボックスへの切替、明示的に別の編集へ移る操作で切り替える。入力を変えた再送は黙って成功にせず409と下書きを保持する。キーなしの従来Connect APIは互換性を維持する。CSV/1PUXの一括処理・再開は別契約として未完を残す。

## 実行と受入

正式backend DockerfileでRustをビルドし、APIがその実行ファイルへJSONを標準入力で渡す。子には資格情報の環境変数を渡さず、5秒の期限・入力2MiB・出力4MiBを設け、内部診断を応答へ出さない。開発時は `cargo build --manifest-path backend/native/Cargo.toml --release` の出力を `PASSSHARE_MUTATIONS_BIN` に指定する。未配置なら503として入力を保持する。

必須検査は、原本の全文保持、古い版409、同一・異なるキー、変更入力、同時送信、他人の拒否、DB再起動後の再送、ボックスと所属の一括保存、実Webの応答喪失と本人切替である。Rustの原本テストと実HTTP受入を専用CIで実行する。実Mobile/Desktop、署名配布、復旧、本人確認、クラウド暗号化と販売全体の22受入は、それぞれの元ToDoを維持する。検査が完了するまでこの仕様を成功記録として使わない。
