# 旧形式から暗号化形式への移行準備（Core）

元 ToDo1163 の M4-C について、完全な項目 JSON と全添付を暗号化する有限の Core API を実装する。準備の成功は、サーバーでの一括確定、画面からの移行、全クライアント、製品全体の受入の成功を意味しない。

## 呼出元と Core の責任

公開入口は `passshare_core::cloud_crypto::migration::prepare_migration`。既存の私有 `PasswordBoxKey` を借用し、既存の項目暗号化と `encrypt_attachment` を使う。生の鍵を取り出す API は追加しない。依存、暗号方式、取込処理、保存処理は追加しない。

呼出元は以下を独立して供給する。暗号文の context から expected を作らない。

- `TrustedOwnerKeyContext`：移行先パスワードボックス ID、所有者 UUID、鍵世代。constructor は形式だけを確認する。Rust の入力値だけで、所有権・権限・鍵の新しさを証明しない。
- `operation_id`：nil でない UUID。同じ計画の再利用で維持する。
- 移行元パスワードボックス ID と正の `source_revision`：後のサーバー取引で検査する前提条件。平文のハッシュは計画に含まず、版番号そのものも現在状態の証明にはならない。
- 項目ごとの完全な JSON オブジェクトと、添付ごとの元 context・UTF-8 名・実バイト。所有する平文型には Debug・Clone・serde を付けない。
- 元と先の `ItemContext`、全添付の元と先の `AttachmentContext` を持つ明示的な対応表。項目順は入力順、添付順は元 JSON の参照順とする。

呼出元が所有者用の新しい鍵を生成し、その同じ鍵を既存 `wrap_for_owner` で所有者の root key に包む。Core 準備に渡した鍵と所有者 bundle の同一性・永続化・後の取引への組込みは呼出元の責任であり、この API は bundle を生成・送信しない。鍵は `&PasswordBoxKey` のまま使い、準備中に交換しない。元と先の鍵世代は変えられるが、項目版・添付版は元から保持する。17 を 1 に戻さない。鍵更新の既存処理をこの移行 API で置き換えない。

## 完全な JSON と明示的な経路対応

入力 JSON の `id`、`version`、`vault.id` は独立した元 ItemContext と一致必須。ID は既存 ConnectId の26桁英小文字・数字。版と鍵世代は整数1〜9007199254740991。元と先の項目版は一致必須。所有者 UUID は nil を拒否する。

`attachments` があれば配列とし、各参照の `attachmentId`、`attachmentVersion`、`keyEpoch` を独立した元 AttachmentContext と照合する。省略は参照0件、null や別形式は拒否する。各添付は元・先の項目とパスワードボックスに厳密に所属し、各々の鍵世代が項目と一致する。参照上の追加属性は保持する。任意の `name` / `contentBytes` 属性が存在する場合は実名・実バイト数との一致も確認する。参照に名前がなければ、添付入力の名前を暗号化して保持する。

復号する既存 `EncryptedItem` の平文は、以下の**独立した外側オブジェクト**である。

```text
{
  id: 移行先項目ID,
  version: 元と同じ項目版,
  vault: {id: 移行先パスワードボックスID},
  attachments: [{attachmentId: 先ID, attachmentVersion: 元の添付版, keyEpoch: 先世代}, ...],
  original: 元の完全なJSONオブジェクト
}
```

これはこの Core API の暗号化 payload 契約であり、取込フォーマットや新しい製品名ではない。移行先の ID が変わる場合でも、元 JSON 内の ID・パスワードボックス参照・添付参照を一切書き換えない。元 JSON に `original` など同名属性があっても、外側とは別の階層として保持する。対応表は公開計画の `binding` に保存する。既存の添付参照検査と接続する際は外側の参照と独立 expected を使う。

保存する元オブジェクトは JSON 値として完全一致する。未知属性、複数 URL、URL の追加属性、null、配列順、添付の追加属性を保持する。元 JSON の文字列としての空白・属性順・数値表記は `serde_json::Value` の契約外で、元のファイル bytes の複製を意味しない。Value 化前の重複 JSON 属性は復元不能なので、取込側が曖昧な属性を拒否する必要がある。重複した項目 ID・参照 ID・対応先 ID は Core が拒否する。添付 ID はこの有限集合のパスワードボックス全体で一意とする。同じ名前や同じ本文を持つ別 ID の添付は許可する。

後のクライアントは、この外側オブジェクトから `original` を取り出し、完全 DTO を保って編集する必要がある。タイトルだけの編集で未知属性・別 URL・添付参照を落としてはいけない。型付き `domain::Item` を経由して完全 DTO とみなすことはできない。現在の Item は URL の拡張を持つが、未知の項目属性や項目版・添付を完全には表現しない。

## 全添付と上限

参照・対応表・実バイトの集合が完全に一致することを暗号化前に検査する。添付入力の順は任意だが、出力は元 JSON 参照順。欠落、余分、同数でも別 context、重複、別項目・別パスワードボックス、版不一致を拒否する。メタデータだけで成功する経路はない。空ファイルは長さ0の実 Vec として渡す。本文の真偽・元ファイルの完全性は、信頼した取込元から呼出元が確保する責任がある。版・context・長さだけで任意の元本文を認証できると主張しない。

| 対象 | 技術上限 |
|---|---:|
| 項目 JSON（元と、外側を含めた暗号化平文の両方） | 1MiB |
| 添付本文1個 | 1MiB |
| 添付名1個 | 4096 UTF-8 bytes |
| パスワードボックスの全添付 | 1024件 |
| 全項目の暗号化平文 JSON ＋全添付本文＋全名前 | 1GiB |

項目の上限には外側オブジェクトの増分も含める。超える場合、属性を削って収めず拒否する。全量は checked arithmetic で加算する。暗号文・Base64・計画の同時生存メモリはこの平文量より大きい。通信上限や商用プラン上限の達成を意味しない。全量上限は加算器の境界と overflow を検査し、1GiB を実際に確保するテストは行わない。

`MigrationItemPlaintext` は所有する JSON の文字列・未知属性名を drop で消去し、拒否された過深 JSON も反復処理で破棄する。添付名と bytes は既存 `AttachmentPlaintext` が消去する。暗号化中の JSON bytes は既存 Zeroizing buffer を使う。呼出元が残した元データやコピーは呼出元が管理する。プロセスの強制終了時の消去は保証しない。

## 安定した計画と確定の境界

`PreparedMigration` は operation ID と読み取り専用の項目・添付暗号文を公開する。`replay_bytes()` は準備時に一度 Serialize した format 1 の bytes を返す。計画は公開経路、元と先の対応、元の状態版、暗号文と nonce のみで、鍵・所有者 root key・本文・名前・平文ハッシュ・ネットワーク処理を含まない。

同じ計画の bytes を再利用すると operation ID・nonce・暗号文は変わらない。同じ operation ID で prepare を再実行すると新しい nonce になり、同じ計画にはならない。呼出元は計画の bytes を保持し、後の認証付き status 確認に基づいて明示的に再利用する。Core はネットワーク再試行を行わない。永続化した bytes の再読み込み・検証と送信プロトコルは後の接続で定める。

準備にはファイル・DB・ネットワークの入口がなく、元を immutable borrow する。成功・エラー・計画の破棄で元を消したり状態を切り替えたりしない。後の取消し・仮置き失敗・確定失敗でも、呼出元は元データを保持し続ける。サーバーの一括確定を確認する前に元を削除しない。

親が実装するサーバー取引では、認証された所有者、同じ元状態版、元の全生存項目・添付と版、先の全件数・対応、同じ鍵の所有者 bundle、並行編集・削除・仮置きの期限・再送の同一性を検査し、まとめて公開状態を切り替える必要がある。この Core 準備には、その取引やロールバックを実装したとする証拠はない。

## 形式の読取と未完の受入

この API は呼出元が復号・展開した完全 DTO を受け取る。`.pbox`、CSV、1PUX の全形式を解析する API ではない。既存 `.pbox` の `PasswordBox::open/recover` は読取用として使えるが、型付き `list_connect_items` の結果を完全 JSON とみなさない。完全性が必要なら既存 `PasswordBoxFile::load_from_path`、保存された KDF の検査・鍵導出、既存 `crypto::decrypt` に基づく読み取り境界で完全 JSON を取得する。復旧形式の検査は既存の契約に従う。Core 準備自身は読み取り・取込も実行しない。

元フォーマットに版や本契約の参照がない場合、親が定めるアダプターで由来と独立した版・参照を明示する必要がある。この API 内で元の未知属性を書き換えたり、暗黙に版1を補ったりはしない。CSV の欠落情報や1PUXの未解析部分を復元できるとは主張しない。

API・SDK・WASM・GUI の接続、全形式アダプター、暗号化状態へのサーバー一括確定、実サービス、全クライアント、M4 と製品全22条件の受入は親担当の未完作業。今回の検証は Core の実暗号化→既存復号、完全 DTO・名前・任意 bytes・順序・版・独立 context、集合不一致・重複・上限拒否、元ファイル保持、所有者 bundle の既存経路に限定する。
