# 所有者キーバンドルAPI

共有ToDo #1163 / #1175、M4の一部です。暗号化したパスワードボックスの鍵を、所有者本人のクライアントが
包んだ不透明なバンドルとして保存・取得するだけの契約です。M4全体は未完です。

## 有効化と認証

[暗号文保存API](encrypted-storage-api.md) と同じ `PASSSHARE_ENCRYPTED_STORAGE=true` の明示的な有効化、
PostgreSQL、native実行ファイルが必要です。無効時は404で、既定は無効です。
暗号化済み（`encrypted`）のパスワードボックスだけが対象で、互換ボックスは409 `PS055` です。

- 生きているセッションと、現在の確認済み **所有者** だけが読み書きできます。
- Connectトークン、`x-passshare-client` の名乗りでは通りません。Cookieの書込みは既存のCSRF検証を通します。
- 共有ボックスの確認済みメンバー・未確認者・元所有者は403です。所有者の移譲後、元の所有者は読み書きできません。
- バンドルは所有者のアカウントごとに分かれ、同じボックスの他人には見えません。

## HTTP契約

| 操作 | パス | 本文・応答 |
|---|---|---|
| GET | `/api/encrypted/boxes/:boxId/owner-key` | `{bundleVersion,bundle}`。未保存は404 `PS012` |
| PUT | `/api/encrypted/boxes/:boxId/owner-key` | 初回は `{expectedVersion:0,bundle}`。上書きは `{expectedVersion,bundle,currentPassword}`。成功は200と `{bundleVersion,bundle}` |

初回は期待版0で版1、以降は比較して+1です。期待版は0〜9007199254740990です。
DELETE・鍵世代の更新・平文移行はこのAPIにありません。

上書きの `currentPassword` は現在のログイン用パスワードです。暗号化パスワードとは別です。
セッションだけを奪われて唯一の包み鍵を壊されないよう、上書き前に既存のArgon2認証で再確認します。
Nodeの接続部がこの認証情報を除き、Rustの公開ヘッダー検査にも保存するバンドルにも渡しません。
SQLはボックス、ユーザー、セッション、所属の順でロックし、確認済みの認証ハッシュのSHA-256と
現在値から計算したSHA-256を照合してから版の条件付き更新を行います。
SQLの引数にArgon2のハッシュ自体を渡さず、確認後にパスワードが変わっていれば拒否します。
既存のIP上限と失敗時のアカウント施錠を、通常のログイン・アカウント変更と共有します。

| 状態 | HTTP / コード |
|---|---|
| セッションなし・失効 | 401 / PS024 |
| 上書きの再認証なし・誤り・古い認証値 | 401 / PS026 |
| 所属なし・未確認 | 403 / PS016 |
| 確認済みメンバーだが所有者でない | 403 / PS032 |
| ボックスなし・包み鍵なし | 404 / PS044・PS012 |
| 互換状態・鍵世代の不一致・版の競合 | 409 / PS055・PS056・PS015 |
| 公開形式・保存先・所有者の違い | 400 / PS051 |
| 試行上限 | 429 / PS028・PS029 |

GETでも現在の鍵世代と保存した世代が違えば409です。公開形式・保存先の検査、上書き時の上限と
再認証、DBでのセッション・所属・状態の検査の順です。他人の文脈を付けた要求は400になります。
正しい自分の文脈で権限だけがない要求は403ですが、上書きで再認証が欠ければ先に401になります。

## バンドルの形式（クライアントが作る公開形式）

```json
{"format":1,"salt":"<16バイトのBase64>",
 "wrapped":{"format":1,
   "context":{"passwordBoxId":"<26桁の英小文字・数字>","ownerAccountId":"<UUID>","keyEpoch":1},
   "nonce":"<24バイトのBase64>","ciphertext":"<48バイトのBase64>"}}
```

- サーバーは公開ヘッダーだけを厳密に検査します。未知フィールド、平文・パスワード・KDF指定の付加は400です。
- `format` は固定で1です。標準Base64はcanonical（再エンコードで一致）が必要です。
- `passwordBoxId` はURLのボックス、`ownerAccountId` はミドルウェアが決めた現在のアカウント（nilと大文字は不可）と
  一致する必要があります。`keyEpoch` は1〜9007199254740991で、現在の鍵世代と一致しなければ409 `PS056` です。
- 鍵導出はクライアントのArgon2id固定値（64MiB / 3 / 4）です。サーバーはパラメーターを受け取りません。
- 暗号化パスワードも生の鍵もサーバーに渡らず、サーバーは復号できません。AEADの正当性はサーバーでは判定できません。
  クライアントは取得後にCoreの `unwrap_for_owner(bundle.wrapped, masterKey, expectedContext)` で検証します。
  展開した鍵が保存済みの項目を復号できることも確認してから使用します。

## 競合と原子性

期待版が現在版と違えば409 `PS015` で、保存済みの内容は変わりません。同じ期待版の同時更新は1件だけ成功します。
SQLは `passshare_owner_key_operation` の1トランザクションで、ボックス行を先にロックし（項目操作・退会・有効化と同順）、
ロック下でセッションと現在の所有者を再確認します。テーブル `encrypted_owner_keys` は
`encrypted_box_state`（ボックス削除）と `users`（アカウント削除）への連鎖削除です。

## 制限

- 所有者の移譲でこのAPIは鍵を包み直しません。新しい所有者は、将来の共有鍵の設計で同じボックス鍵を
  別の経路で入手したうえで、自分のバンドルを作る必要があります。
- 所有者移譲・メンバー除外は、既に取得された暗号鍵や暗号文の失効ではありません。
  暗号的な失効は、残るメンバーへの鍵の世代更新と項目の再暗号化を実装して確認します。
- アカウントの認証の復旧では暗号化鍵は復旧しません。別の暗号化パスワードが引き続き必要です。
- 暗号化パスワードの変更、鍵世代の更新、バンドルの削除・失効は未提供です。

## 検証

- native単体: `owner_key` の公開ヘッダー検査（範囲・形式・Base64・スコープ・未知フィールド）。
- 独立受入tool `tools/encrypted-storage-acceptance`: 正式API経路とPostgreSQLで、Core生成のバンドルのGET/PUT、
  取得したソルトからの再導出とCoreでの展開・項目復号、CAS（古い版の拒否と原本保持、同時更新1成功／3競合）、
  再起動後の保持、移譲・失効済みセッション・メンバーの拒否、ボックスとアカウントの連鎖削除を確認します。
  サーバーはCoreに依存しません。

正式NodeとPostgreSQLの独立受入で、上書きの再認証・誤った認証後の原本保持、
有効なCookieとCSRFの保存、正式所有者移譲後の拒否・再取得、再起動後の復号まで成功しました。
native49件と独立契約4件、Clippyも成功しています。正式配布イメージと最終候補のCIは別に確認します。

鍵世代の更新、平文移行と故障時の原本保持、暗号化した添付、プラン上限、削除契約、公開環境での受入です。
